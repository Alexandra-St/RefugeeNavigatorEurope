# Private Beta session checklist

## Before the session

- [ ] Record the current deployed commit SHA from the release/deployment record; do not assume the latest `main` commit is deployed.
- [ ] Confirm the Private Beta site is accessible.
- [ ] Share access credentials separately; never put them in notes, feedback, or screenshots.
- [ ] Explain that the session requires no personal data and that hypothetical situations should be used for guides.
- [ ] Have the current [tester guide](TESTER_GUIDE_EN.md), [scenarios](USER_SCENARIOS.md), and blank [observation record](OBSERVATION_TEMPLATE.md) ready in the tester’s preferred language where available.

## During the session

- [ ] Avoid coaching; allow natural navigation and pauses.
- [ ] Record observations separately from interpretation.
- [ ] Do not ask about real immigration history, status, applications, or personal eligibility.
- [ ] Note when a guide is perceived as making an individual legal/status decision.
- [ ] Do not capture or retain credentials or personal information.

## After the session

- [ ] Classify findings using Critical, Major, Minor, or Suggestion.
- [ ] Reproduce functional issues where possible without personal data.
- [ ] Deduplicate repeated observations while preserving useful context.
- [ ] Separate UX/usability issues from content/legal questions; route legal questions for source and editorial review.
- [ ] Create actionable follow-up items with reproducible steps and no identifying details.

## Manual accessibility spot checks

This is a small usability check, not a full WCAG audit. Check keyboard navigation and visible focus; language switching; search and comparison forms; guide controls; 200% text zoom and narrow reflow; and obvious, understandable source-link behavior. See the project’s [accessibility remediation plan](../accessibility/REMEDIATION_PLAN.md).
